# ระบบจองโต๊ะคอนเสิร์ต ร้านบ้านตะลุง (ฉบับเชื่อมฐานข้อมูลจริงบน Turso)

โครงสร้างโปรเจกต์:
```
bantalung/
├── backend/     ← Express API + ฐานข้อมูล Turso (Cloud SQLite)
└── frontend/    ← index.html, style.css, app.js (เรียก API จริง)
```

## สิ่งที่เปลี่ยนจากเวอร์ชันเดิม
1. **ฐานข้อมูลจริงบน Turso (Cloud)** แทน `localStorage` และแทนไฟล์ SQLite บนเครื่อง — ผังโต๊ะ, การจอง, ราคา ถูกเก็บบนคลาวด์ ทุกคนที่เข้าเว็บเห็นข้อมูลตรงกัน **และข้อมูลไม่หายแม้ deploy บนโฮสติ้งฟรีที่ไม่มี Persistent Disk** (เช่น Render free tier)
2. **ระบบจองทำงานได้จริง** — กันจองโต๊ะซ้ำด้วย transaction ในฐานข้อมูล (ถ้าลูกค้า 2 คนกดจองโต๊ะเดียวกันพร้อมกัน จะมีแค่คนแรกที่จองสำเร็จ)
3. **ความปลอดภัย**
   - รหัสผ่านแอดมิน **ไม่ได้ hardcode ในโค้ดฝั่ง client อีกต่อไป** เข้ารหัสด้วย bcrypt เก็บใน DB
   - เข้าสู่ระบบแอดมินผ่านฟอร์ม login จริง ได้ JWT token (หมดอายุอัตโนมัติ)
   - จำกัดจำนวนครั้ง login ผิด (กัน brute-force รหัสผ่าน)
   - Validate/sanitize ข้อมูลจากผู้ใช้ทุกจุด กัน XSS
   - จำกัดชนิดไฟล์สลิป (เฉพาะรูปภาพ) และขนาดไม่เกิน 5MB

## ⚠️ สิ่งที่ยังไม่เปลี่ยน — สำคัญมากถ้าจะ deploy บนโฮสติ้งฟรี
**ไฟล์รูปภาพ (สลิปโอนเงิน, รูปเมนูอาหาร) ยังเซฟลงดิสก์เครื่องเซิร์ฟเวอร์อยู่ (`backend/uploads/`) ไม่ได้ย้ายไป Cloudinary หรือที่เก็บไฟล์บนคลาวด์อื่น** ถ้า deploy บน Render free tier (ไม่มี Persistent Disk) รูปเหล่านี้จะหายทุกครั้งที่เซิร์ฟเวอร์รีสตาร์ท/redeploy แม้ข้อมูลในฐานข้อมูล (ชื่อลูกค้า, สถานะจอง ฯลฯ) จะไม่หายแล้วก็ตาม — ถ้าต้องการแก้จุดนี้ด้วย (ย้ายไป Cloudinary) แจ้งได้

หน้าจัดการโปสเตอร์ก็ยังเก็บด้วย `localStorage` ของเบราว์เซอร์เช่นกัน (ยังไม่ sync ข้ามอุปกรณ์)

## วิธีติดตั้งและรัน

### 1. สร้างฐานข้อมูล Turso (ทำครั้งเดียว)
1. สมัครบัญชีฟรีที่ [turso.tech](https://turso.tech)
2. ติดตั้ง Turso CLI แล้ว login ตามคู่มือในเว็บ (หรือสร้างฐานข้อมูลผ่านหน้าเว็บ Dashboard ก็ได้ ไม่จำเป็นต้องใช้ CLI)
3. สร้างฐานข้อมูลใหม่ 1 ตัว (ตั้งชื่ออะไรก็ได้ เช่น `bantalung`)
4. คัดลอกค่า **Database URL** (ขึ้นต้นด้วย `libsql://...`) และสร้าง **Auth Token** เก็บไว้ จะใช้ในขั้นตอนถัดไป

### 2. สร้างบัญชี Cloudinary (ทำครั้งเดียว)
สำหรับเก็บรูปภาพ (สลิปโอนเงิน, รูปเมนู, โปสเตอร์) แทนการเก็บลงดิสก์เครื่องเซิร์ฟเวอร์
1. สมัครบัญชีฟรีที่ [cloudinary.com](https://cloudinary.com)
2. เข้าหน้า Dashboard หลังสมัคร จะเห็น **Cloud Name**, **API Key**, **API Secret** แสดงอยู่หน้าแรกเลย คัดลอกเก็บไว้

### 3. ติดตั้ง backend
```bash
cd backend
npm install
cp .env.example .env
```

เปิดไฟล์ `.env` แล้วแก้ค่าต่อไปนี้:
- `JWT_SECRET` — สุ่มค่าใหม่ด้วยคำสั่ง `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` แล้วคัดลอกมาแปะ (ห้ามใช้ค่า default)
- `TURSO_DATABASE_URL` — ค่าที่ได้จากขั้นตอนที่ 1
- `TURSO_AUTH_TOKEN` — ค่าที่ได้จากขั้นตอนที่ 1
- `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` — ค่าที่ได้จากขั้นตอนที่ 2

### 4. สร้างบัญชีแอดมิน (ครั้งแรกเท่านั้น)
```bash
npm run seed:admin
```
ระบบจะเชื่อมต่อ Turso อัตโนมัติ (สร้างตารางทั้งหมดให้ถ้ายังไม่มี) แล้วถามชื่อผู้ใช้ (ปล่อยว่างได้ จะใช้ `admin`) และรหัสผ่าน (อย่างน้อย 10 ตัวอักษร) — **จำรหัสผ่านนี้ไว้ให้ดี ไม่มีการเก็บ plaintext ไว้ที่ไหนเลย** ถ้าลืมให้รันคำสั่งนี้ซ้ำเพื่อเปลี่ยนรหัสผ่านใหม่ได้ตลอด

### 5. รัน backend
```bash
npm start
```
เซิร์ฟเวอร์จะรันที่ `http://localhost:3000` (แก้พอร์ตได้ในไฟล์ `.env`) ครั้งแรกที่รันจะเชื่อมต่อ Turso แล้วสร้างผังโต๊ะเริ่มต้นให้อัตโนมัติ

### 6. เปิด frontend
เปิดไฟล์ `frontend/index.html` ผ่าน live server ใดก็ได้ เช่น VS Code "Live Server" extension หรือ:
```bash
cd frontend
npx serve .
```

ถ้า frontend รันคนละพอร์ต/โดเมนกับ backend ให้แก้ 2 จุด:
- `frontend/app.js` บรรทัดแรก: `const API_BASE = 'http://localhost:3000';` ให้ตรงกับที่ backend รันอยู่
- `backend/.env` ค่า `FRONTEND_ORIGIN` ให้ตรงกับ URL ของ frontend (สำหรับ CORS)

### 7. เข้าใช้งาน
- หน้าลูกค้า: เปิด `index.html` ได้เลย เลือกโต๊ะ กรอกฟอร์ม แนบสลิป
- หน้าแอดมิน: กดปุ่ม "⚙️ Admin Mode" มุมขวาบนของแบนเนอร์ แล้ว login ด้วยชื่อผู้ใช้/รหัสผ่านที่สร้างไว้ในขั้นตอนที่ 2

## หมายเหตุด้านความปลอดภัยก่อนใช้งานจริง (production)
- ต้อง deploy backend ผ่าน HTTPS เท่านั้น (ไม่งั้น token/รหัสผ่านที่ส่งผ่านเน็ตเวิร์กจะไม่ถูกเข้ารหัส)
- โฟลเดอร์ `backend/uploads` เก็บสลิปการโอนเงินของลูกค้า (ข้อมูลอ่อนไหว) — ควร backup และจำกัดสิทธิ์การเข้าถึงที่ระดับ hosting/ไฟล์ระบบด้วย ไม่ใช่พึ่งแค่ชื่อไฟล์สุ่ม
- ไฟล์ `.env` ห้าม commit ขึ้น git หรือแชร์ให้ใครเห็นเด็ดขาด (มี `JWT_SECRET` อยู่ในนั้น)
- แนะนำตั้ง reverse proxy (เช่น Nginx) หน้า backend และเปิด rate limit เพิ่มเติมตามทราฟฟิกจริง
